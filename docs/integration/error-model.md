# Error Model

Status: reviewed
Related: FR-27, NFR-07, ADR-013
Verified against: no dependency claims

## 1. Shape

```ts
type ApiError = {
  statusCode: number;
  code: ErrorCode;
  message: string;
  details: Record<string, string[]> | null;
  requestId: string;
  timestamp: string;
  path: string;
};
```

- `message` is for humans and may change. Clients branch on `code`.
- `details` is populated only for `VALIDATION_FAILED`, mapping field → messages.
- `requestId` is generated per request and echoed in logs. It is always generated by the
  server (a client-supplied `X-Request-Id` is ignored) and returned in the `X-Request-Id`
  response header as well as the body.
- `path` is the request path without its query string, because query strings can carry
  sensitive values.

## 2. Codes

| Code | Status | Meaning | Typical cause |
|---|---|---|---|
| `AUTH_REQUIRED` | 401 | No valid session | Missing, expired, or tampered cookie |
| `AUTH_INVALID_CREDENTIALS` | 401 | Email or password wrong | Login failure (undifferentiated) |
| `AUTH_EMAIL_TAKEN` | 409 | Email already registered | Registration |
| `VALIDATION_FAILED` | 422 | Payload shape or value invalid | Missing field, weak password, empty message |
| `FILE_TOO_LARGE` | 413 | Upload or JSON body exceeds its limit, or extracted text exceeds `MAX_EXTRACTED_CHARS` | Parser limit; a small archive that unpacks to a lot of text |
| `UNSUPPORTED_FILE_TYPE` | 415 | Extension, MIME, or signature rejected | Non-PDF/DOCX/XLSX or mismatch |
| `EMPTY_EXTRACTION` | 422 | No extractable text | Scanned PDF |
| `EXTRACTION_FAILED` | 422 | Parser error | Corrupt or unsupported inner structure |
| `PROCESSING_TIMEOUT` | 504 | Extraction exceeded the budget | Very large or pathological file |
| `DOCUMENT_NOT_FOUND` | 404 | No such document for this user | Unknown id or another user's id |
| `CONVERSATION_NOT_FOUND` | 404 | No such conversation for this user | Unknown id or another user's id |
| `AI_TIMEOUT` | 504 | Provider did not answer in time | Upstream latency |
| `AI_UNAVAILABLE` | 503 | Provider error after one retry | Upstream outage, bad key, quota |
| `RATE_LIMITED` | 429 | Too many requests | Limit exceeded |
| `FORBIDDEN_ORIGIN` | 403 | Request came from a disallowed browser origin | Forged `Origin` or cross-site write |
| `NOT_FOUND` | 404 | Unknown route | Typo or removed endpoint |
| `INTERNAL` | 500 | Unexpected server error | Bug; details only in logs |

The union and the constant object live in `packages/contracts/src/errors.ts`. Adding a
code requires updating this table in the same change.

## 3. Mapping rules

| Thrown thing | Maps to |
|---|---|
| `UnauthorizedException` | `AUTH_REQUIRED` |
| `AuthError('invalid_credentials')` | `AUTH_INVALID_CREDENTIALS` |
| `ValidationError` from pipes | `VALIDATION_FAILED` + `details` |
| Domain `NotFoundError(kind)` | `<KIND>_NOT_FOUND` |
| File validation error | Its specific code |
| Provider timeout | `AI_TIMEOUT` |
| Provider non-2xx after retry | `AI_UNAVAILABLE` |
| Anything else | `INTERNAL`, generic message |

Unhandled errors are logged with request metadata and `requestId`, without the original stack or message; the response never contains a
stack, a SQL fragment, or an upstream body.

## 4. Ownership and existence

A resource that exists but belongs to another user returns the same 404 code as a
nonexistent resource. This is intentional: confirming existence is an information leak.
Ownership checks never return `403`. The only `403` is `FORBIDDEN_ORIGIN` at the HTTP edge.

## 5. Client handling (Angular)

The error interceptor normalises `HttpErrorResponse` into a client-side `AppError`:

```ts
type AppError = { code: ErrorCode | 'NETWORK' | 'UNKNOWN'; message: string; details?: Record<string, string[]> };
```

| Condition | Behaviour |
|---|---|
| 401 `AUTH_REQUIRED` | clear auth store, redirect to `/login?returnUrl=...` |
| 429 | show "too many requests, try again in a moment" |
| `VALIDATION_FAILED` | bind `details` to form controls |
| `NETWORK` (status 0) | "cannot reach the server", keep the user's input |
| 5xx | generic message plus the `requestId` for support |
| other 4xx | show `message` |

Rules:

- Never render `message` from an unknown source as HTML.
- Never swallow an error silently; every failure reaches a visible state.
- A failed chat request keeps the typed question in the composer.

## 6. Logging

Log one line per request at completion:

```
level=info requestId=... method=POST path=/api/documents/upload status=201 durationMs=842 userId=...
```

For errors, add `code` and the stack (server-side only). Never log bodies, cookies,
tokens, prompts, completions, or document text. A redaction test asserts that a request
carrying `password`, `authorization`, and `cookie` produces a log line containing none of
their values.

## 7. Testing the model

- A test per code path that asserts `statusCode`, `code`, and the envelope keys.
- A test that an unknown exception yields `INTERNAL` with no stack in the body.
- A test that `VALIDATION_FAILED` includes `details` keyed by field.
- A test that a foreign resource returns `*_NOT_FOUND`, not `403`.
